# ADR-025: URL-state completion and the /play route - one bus, one gesture, byte-compatible links

- Date: 2026-09-28
- Status: Accepted (PRD-001 Phase 8 Slice 1, D145..D151)
- Context: REQ-IO-50 (P0, the PRD's last open P0) demanded URL serialization for ALL modes; etude + compose shipped, practice + explore serialized nothing. REQ-IO-52 wanted a /play route in an app with zero router and no Vercel SPA fallback. The debounced single writer lived inline in App.tsx, and share-copy could race it.

## Decision

1. **"All modes' state" adjudicated as MUSICAL SESSION state** (D145/D146/D151): practice ships 4 keys (path/bpm/persona/voicing) - one truth per legacy-hook field, defaults-delete-keys, etu-* paths NEVER ride path= (they regenerate via the 13 etude keys, guarded BOTH serialize and parse); explore ships ONE key (eseed) because the PRD's own 11.2 designs explore as mode+seed and the seed deterministically regenerates the session. Playheads, mechanics ergonomics, detection/note-input gates, and latency are device noise - explicitly excluded, PRD reading note applied. The P0 closes honestly instead of lying open under an impossible literal reading.
2. **Boot-merge on the live-list projection** (D145): practice path restore resolves BY ID AFTER the etude prepend, against a virtual `livePaths = [prependedEtude, ...paths]` - the index-shift/wholesale-restore class (PHASE-4-01 HIGH-001) killed by construction; unknown id silently drops.
3. **Writer -> urlSyncBus: behavior-preserving extraction** (D149): the 200ms debounce + pagehide synchronous flush law MOVED verbatim from App into a zero-history-calls scheduler module; App registers the ONE writer (single replaceState site, grep-pinned). The predicate widened 4->6 terms with both-direction pins per term. The shipped etude/compose/upload e2e round-trip legs passed UNTOUCHED - that is the extraction's regression net.
4. **Flush-before-copy law** (D149): every Share affordance synchronously flushes the pending write BEFORE reading location.href - a copy clicked inside the debounce window would otherwise ship a stale URL. Pinned by a literal call-ORDER assertion (["write","copy"]), not a status check. This is the URL sibling of the pagehide rule: any reader of the URL must first force any pending writer.
5. **popstate: structurally unwired, by design** (D147): a replaceState-only writer creates NO history entries - there is nothing to pop; back/forward navigates the URL, which is the honest contract. The narrow alternative (popstate only for ?idea=) was proven dead on the same reasoning. TD-027 closes resolved-by-design; real back/forward state-restoration would require a pushState product decision, not a bug fix.
6. **/play = armed one-gesture, no router** (D148): one `isPlayRoute ? PlaySurface : App` branch in main.tsx (App NEVER mounts on /play - no boot side effects leak; e2e pins URL invariance as the proxy). Browsers forbid cold autoplay, so "immediately plays" was erratumed to ARMED + one click (autofocus); chord/progression/melody play via the shipped preview singleton (pre-click audio silence pinned), scale/seed open an honest CTA. Reachability: vercel.json gains /play + /play/ rewrites (NO catch-all), public/serve.json mirrors it for the e2e static server - previews 404 until this deploys (tracked).
7. **Byte-compatible idea codec** (D149): ideaShare.ts replicates the shipped `btoa(encodeURIComponent(JSON))` scheme with pins computed against an INDEPENDENTLY replicated encode/decode - links already circulating keep working; the stale "not yet implemented -- Phase 8" console warn died with it (unit + e2e console-collector no-warn pins).

## Consequences

- REQ-IO-50 P0 CLOSED (all modes, per the recorded reading); TD-027 + TD-047 CLOSED; the PRD carries three Kai errata (IO-50 reading, IO-52 gesture+carve, 11.2 tmode/eseed examples).
- Suite 2664 -> 2743 (+79 exact per-file allocations), e2e 34 -> 41 (16 specs); break-guard: all 7 new legs fail pre-S1. JSDOM_FILES +2 (urlSyncBus, shareUrl); purity floor 56 untouched (zero engine files).
- Prevention rule S8-001: any UI that reads the live URL (copy/share/open-in-new) must flush pending debounced writers synchronously first - call-order pinned.
- Follow-ups filed: TD-061 (explore-share omits >1500-char ideas - governor asymmetry), TD-062 (pre-existing ?mode=explore&idea= boot-order gap - D-1 fixed only the eseed channel), TD-063 (pagehide->flush WIRING in App is manual-only - the contract is pinned, the call site is not), TD-064 (share-affordance hygiene: IdeaBar disabled-title, bus unregister timer).
