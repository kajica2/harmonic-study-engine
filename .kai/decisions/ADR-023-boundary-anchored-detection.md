# ADR-023: Played-correctly detection - boundary-anchored matching on read-only transport seams

- Date: 2026-09-27
- Status: Accepted (PRD-001 Phase 7 Slice 3)
- Context: REQ-PRAC-40..42/50..54/60..62 + REQ-PRAC-33: latency calibration, per-bar played-vs-expected detection, auto-rated tempo ramp, and practice sessions - all without touching the sacred handler, the frozen guide-tone trail family, or the transport write path.

## Decision

1. **Boundary-anchored phase alignment** (D129): the expected-onset anchor is the wall time the bar's audio EMITTED, observed as performance.now() at the playbackClock rAF tick where the step flips. Chosen over handler-stamped boundaries (zero handler edits - the S1/S2 one-hunk budgets were SPENT; the detector is a pure read-only consumer, TD-052 grep-gated). Interval jitter is absorbed BY CONSTRUCTION: the click and the handler run in the same setInterval callback, so click lateness shifts the anchor identically - the user is never blamed for the app's clock. Expected onsets are bar starts only -> no within-bar interpolation exists to drift. Tolerance floor 120ms (ear-training precedent), app-side worst-case composite ~83ms.
2. **New matcher, not the guide-tone trail** (D130): useGuideToneTrail's denominator is PLAYED notes; REQ-51 needs EXPECTED notes + missed-as-signal + timing + per-bar attribution, and its test file is frozen. Reuse verdict ~40% (subscription shape, pc convention, bass-channel exclusion, the live chip stays the per-note surface). Engine/practice/detect.ts: ZERO imports, timestamps are inputs, bucket law TOTAL (conservation swept 2k grids against an independently re-implemented oracle; matchedFraction NEVER NaN). File named detect.ts (parent sketch said match.ts - task authority, ratified).
3. **The design doc was WRONG about shipped code; the dev caught it** (audit #15 erratum): "optimizedStepsNotes has transpose/voicing baked in" is FALSE - it is voice-leading-only. The sounding-synth array is exportNotesOverride (the WAV-export mirror). The expected grid builds from the latter; following the doc literally would have all-missed every transposed practice session. Lesson generalized: re-audit against SHIPPED code, not prior design prose (W2-001 extended to seams).
4. **Auto-rep rides the shipped repPulse seam** (D132): ramp.ts byte-untouched; App effect on [repPulse] with lastPulseRef edge guard + a PhraseMatch-identity idempotent router (double-rating impossible across the hook's immediate onPass route and the effect fallback). Manual buttons disabled while armed - REFINED in the fix round to `canAutoRate = armed && mode !== "off" && gridTargets > 0`: the bare-armed law soft-locked the ramp for mono-slice trumpet/sax personas (all-free grid -> no verdicts -> no auto-reps -> manual blocked) and for mode-off + ramp. The design's own promised mitigation ("no targets in this form" notice, risk row 5) was unshipped; now shipped + pinned.
5. **Sessions vs takes vs set-runner: three concepts, three keys, no FK** (D133): SessionRecordV1 / practice.sessions / practiceSessions.ts, legacy trio untouched; shape-guard rejects cross-schema rows. Fold caps 50 sessions x 50 raw attempts + running aggregates (summarize-then-drop-raw, quota law); 20s minimum block; appendAttempt (practiceSessions.ts) is the ONLY dual-write seam into pedagogy.log (D136: mode union widened to "practice" in engine + isEntry guard + registry, same commit, spy-pinned).
6. **Canonical latency equation, one sum** (D134): compensated = tap - input - output; input = median-of-16 raw offsets minus browser outputLatency (seconds->ms conversion added in the wizard - the design pseudocode would have made compensation a ~0.02ms no-op); perfect tap = zero residual, pinned. Single-sum law: the engine sees ONE latencyCompensationMs, formed ONLY in compensationOf(). Spacebar source CUT; ear-training dictationTimingOk seam NOT wired (doubly dead - no consumer computes onsetErrorMs; see TD-057).
7. **e2e honesty via the shipped window-"midin" seam** (D135.1): the detector subscribes to the CustomEvent midiIn already dispatches - identical data, injectable from outside, NOT a test-only hook. Positive leg asserts MONOTONIC counters only (data-notes-hit >= 1, some data-match present); per-bar attribution is unit-pinned, never e2e-timed. Break-guard: all 3 legs FAIL on the pre-S3 build (verified live in a git worktree at 13006cf).

## Consequences

- Purity floor 53 -> 56 (detect/latency/session.ts, all zero-import); JSDOM_FILES +2 (hook + wizard).
- Sacred handler byte-identical to 13006cf (independently proven two ways in review + by the S3 diff itself); rhythm/midiIn/midiOut/playbackClock/guideTone family/duty/ramp/windows all outside the diff.
- TD-055..057 opened (unclosed-record cap slots; mid-pass cosmetic pessimism; real-device validation owed incl. the ear-training onset seam).
- Round-trip pin discipline: widening a total-shape normalize breaks every `toEqual(stored)` pin - fixtures must be updated to the NEW complete shape with NON-default values (two S2 pins fixed this way before the pipeline even reached review).
