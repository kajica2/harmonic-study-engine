## 1. Executive Summary

The Harmonic Study Engine today is a guided practice tool: curated paths, style packs, global transposition, a basic generator. It is useful but narrow.

This PRD expands it into a **mode-driven workbench** that serves four distinct jobs-to-be-done across one shared engine:

1. **Compose**  -  bring your own music, get an arrangement.
2. **Etude**  -  generate focused studies for deliberate practice.
3. **Explore**  -  play with harmonic ideas without a fixed goal.
4. **Learn** *(cross-cutting)*  -  understand what you're hearing and playing.

The expansion is delivered through four product layers built on the existing engine:

| Layer | Purpose | Primary modes |
|---|---|---|
| **Generation** | Algorithmic creation of harmony, melody, bass, rhythm | Compose, Etude, Explore |
| **Analysis** | Detecting key, melody, and chords in uploaded music | Compose |
| **Pedagogy** | Annotations, concept library, ear training, progress | All |
| **Practice** | Metronome, looping, tempo ramp, performance feedback | Etude |

Everything runs **client-side**. No MIDI or audio leaves the browser unless the user explicitly shares a link.

## 2. Problem & Opportunity

### 2.1 Current state

The engine has a strong technical foundation  -  voice-leading, modulation, style packs  -  but the product surface is thin. A user opens the app and sees a practice tool, not a workbench. There is no way to bring in their own music, no way to generate targeted exercises, and no way to explore harmonic possibilities.

### 2.2 Problems

| # | Problem | Who feels it |
|---|---|---|
| P1 | No path from user's own music into the engine | Songwriters, producers |
| P2 | Generated content is generic  -  no style shaping, no constraint control | Students, teachers |
| P3 | No explanation layer  -  users learn *what* but not *why* | Beginners, self-taught |
| P4 | No practice mechanics  -  cannot drill, loop, or measure progress | Students |
| P5 | Output is MIDI-only, useless to users without a DAW | Producers, hobbyists |
| P6 | Input is file-only  -  no keyboard, no typing, no drawing | Everyone |
| P7 | The app does one thing well; the audience wants three | All |

### 2.3 Opportunity

- Web MIDI and Tone.js are mature enough for serious browser audio.
- `tonal` and `@tonejs/midi` make music theory and MIDI I/O accessible in the browser.
- The pedagogical music-tech space is dominated by either dry theory apps or black-box AI generators. There is a gap for a **transparent, explainable, hands-on** tool.
- Client-side architecture makes the app fast, private, and offline-capable  -  a genuine differentiator versus cloud-first competitors.

## 3. Vision & Principles

### 3.1 Vision

> A musician opens a browser tab and moves fluidly between composing, practicing, and exploring  -  with one shared engine underneath, one consistent language on top, and honest explanations at every step.

### 3.2 Principles

1. **Analysis is advisory.** Every automatic decision is user-overridable.
2. **Explain everything.** Every generated artifact carries annotations.
3. **Data over code.** Styles, patterns, and constraints are declarative.
4. **MIDI-first.** Numbers internally; names, notes, and staff are derived.
5. **Reproducible.** Same seed + inputs = same output. Always.
6. **Client-side by default.** Privacy is a feature.
7. **Modular surfaces, shared engine.** Modes differ in UI, not capability.
8. **Meet users where they are.** File, keyboard, chord chart, piano roll, Web MIDI  -  all valid entry points.

## 4. Target Users

| Persona | Description | Primary modes | Key needs |
|---|---|---|---|
| **The Student** | Learning theory, taking lessons | Etude, Learn | Structured drills, feedback, progress |
| **The Teacher** | Assigns material, demos concepts | Etude, Explore | Fast generation, explanations, export |
| **The Songwriter** | Has a melody or chord sketch | Compose | Arrangement help, style options |
| **The Producer** | Works in a DAW, needs parts | Compose, Explore | Audio/MIDI export, quick iteration |
| **The Theory Nerd** | Curious about harmony | Explore, Learn | Deep dives, substitutions, naming |
| **The Hobbyist** | Plays for fun, no DAW | Compose, Etude | Audio output, playable parts, low friction |

These personas overlap. The mode selector lets each user find their entry point without a wall of controls.

## 5. Goals & Success Metrics

### 5.1 Product goals

| Goal | Why |
|---|---|
| G1 | Make the app useful for composition, not just practice | Expand audience |
| G2 | Make every generated artifact teach something | Fulfill "study engine" promise |
| G3 | Make practice measurable and structured | Turn a toy into a tool |
| G4 | Remove input and output friction | Match real workflows |
| G5 | Preserve the existing engine's strengths | Don't throw away what works |

### 5.2 Success metrics

**Adoption**
- % of new sessions that use more than one mode (target: >40%)
- % of sessions that use Compose mode with an uploaded file (target: >20%)
- % of sessions that use Etude mode with the practice panel (target: >30%)

**Engagement**
- Median session length (baseline TBD -> target: +50%)
- Return rate within 7 days (baseline TBD -> target: >25%)
- Annotations opened per session (target: >=2)

**Quality**
- Analysis key detection accuracy on golden corpus (target: >85%)
- Generated accompaniment "sounds musical" (qualitative, via user testing, target: >70% approval)
- Generation latency p95 (target: <100 ms for etudes, <500 ms for accompaniment)

**Satisfaction**
- Post-session NPS or thumbs-up rate (target: >70%)

## 6. Product Structure

### 6.1 The mode selector

A persistent top-level control that switches the app between three modes. Mode is always visible, always one click away.

```
+--------------------------------------------------+
|  Harmonic Study Engine                           |
|  [ Compose ]   [ Etude ]   [ Explore ]           |
|  Global transpose: [-12][-1][0][+1][+12]         |
+--------------------------------------------------+
```

### 6.2 The four layers

```
+---------------------------------------------------------+
|                     MODES                               |
|    Compose       Etude        Explore                   |
+---------+-----------+------------+----------------------+
          |           |            |
          v           v            v
+---------------------------------------------------------+
|              SHARED ENGINE                              |
|                                                         |
|  Generation  .  Analysis  .  Pedagogy  .  Practice      |
|                                                         |
|  Styles . Transposition . MIDI I/O . Voicing . Patterns |
+---------------------------------------------------------+
          |           |            |
          v           v            v
+---------------------------------------------------------+
|              ADAPTERS                                   |
|   Tone.js (audio)  .  VexFlow (notation)  .  Web MIDI   |
+---------------------------------------------------------+
```

## 7. Scope

### 7.1 In scope (v1.0 of this PRD)

**Foundations**
- Mode selector with persistence and dirty-state handling
- Style Profiles system with six starter profiles
- Layered transposition (global + exercise + file)
- MIDI-first internal representation
- Seeded reproducible generation
- Shared Idea object for cross-mode handoff

**Compose mode**
- MIDI file upload and parse
- Track role classification
- Key, melody, and chord analysis
- Editable analysis card
- Style-driven accompaniment generation (bass, chords, pad)
- Voicing engine with smooth voice-leading
- Pattern-based rhythm realization
- Combined MIDI export

**Etude mode**
- Constraint-driven generation (key, mode, style, difficulty, bars, tempo)
- Harmony, melody, and difficulty generators
- Transposition per exercise
- Cycle-all-12-keys practice loop
- Staff notation display
- MIDI export

**Explore mode**
- Seed-based exploration (chord, progression, scale, interval, free)
- Reharmonization suggestions with rationale
- Substitution, expansion, and modulation operations
- Idea cards with crossover buttons

**Pedagogy layer**
- Annotation system on every generated artifact
- Concept registry with reference material
- Concept drawer accessible app-wide
- Ear training sub-mode with multiple exercise types
- Spaced repetition for ear training
- Local practice logging and progress summary

**Practice mechanics**
- Metronome with accents, subdivision, sounds
- Count-in before playback
- Section looping
- A/B compare mode
- Tempo ramp with success tracking
- Latency calibration
- Played-correctly detection via Web MIDI
- Practice session model with attempt history

**Extended I/O**
- Web MIDI input
- On-screen piano
- Computer keyboard mapping
- Chord-chart paste input
- Piano-roll editor
- WAV export (full mix and stems)
- MusicXML export
- Print / PDF via browser
- Session sharing via URL
- "Play this" idea links
- Privacy statement on upload

**Non-functional**
- Versioned data models
- Canonical vs instance IDs
- Analysis confidence thresholds
- Graceful error handling in analyzers
- Empty states for every mode
- Playable-range warnings
- Groove/feel selector and humanize slider

### 7.2 Out of scope (explicitly excluded)

- Real-time collaboration
- User accounts or cloud sync
- Native mobile apps
- Multi-track mixing, effects, or automation
- Full notation editing (defer to MuseScore)
- DAW features (recording, plugins, arrangement view)
- Song identification ("what song is this?")
- Social features, feeds, or following
- Monetization and billing (in v1)
- Video or tutorial content
- Microphone pitch detection
- Guitar tab import/export

These may be revisited in later versions.

## 10. Technical Architecture

### 10.1 Layers

- **UI layer**  -  React components, one workspace per mode.
- **Engine core**  -  pure TypeScript, no DOM or audio context access.
- **Adapters**  -  Tone.js, VexFlow, `@tonejs/midi`, Web MIDI, file I/O.

### 10.2 Engine modules

```
engine/
+-- core/            midi, rng, spelling, transpose
+-- styles/          types, profiles, difficulty
+-- compose/         parse, roles, key, melody, harmony, plan, voicing, pattern, bass, assemble, export
+-- etude/           types, harmony, melody, assemble
+-- explore/         seeds, reharmonize, substitute, expand, vary, modulate
+-- pedagogy/        types, concepts, detect, annotations
+-- ear-training/    types, generate, check, srs
+-- practice/        metronome, tempo-ramp, loop, latency, detect, session
+-- io/              webmidi, chordchart, pianoroll, audio-export, musicxml, abc, share
+-- migrations/      schema version migrations
```

### 10.3 Libraries

| Library | Purpose |
|---|---|
| `tonal` | Notes, intervals, scales, chords, roman numerals |
| `Tone.js` | Audio scheduling, synthesis, offline rendering |
| `@tonejs/midi` | MIDI parsing and export |
| `VexFlow` | Staff notation rendering |
| `lamejs` | MP3 encoding (later phase) |
| `fflate` or `jszip` | ZIP for stem export |
| `Zod` | Runtime validation at boundaries |
| `Vitest` | Tests |

All libraries used are permissively licensed (MIT, Apache 2.0, or SIL OFL). Notation fonts must be Bravura (SIL OFL) or equivalent.

### 10.4 State management

- **Local component state** for transient UI.
- **A session store** (Zustand, Redux, or signals  -  implementation's choice) for cross-mode state: mode, global transposition, current idea, per-mode session data.
- **`localStorage`** for persistence: session, ideas library, SRS, practice log, latency calibration, settings.
- **No server-side storage** in v1.

### 10.5 Performance targets

| Operation | Target p95 |
|---|---|
| Parse + analyze 3-min MIDI | < 500 ms |
| Generate etude | < 100 ms |
| Generate accompaniment | < 500 ms |
| Audio playback latency | < 20 ms |
| Mode switch | < 100 ms |
| First contentful paint | < 1.5 s on 3G |

### 10.6 Offline / PWA

Ship as a PWA with service worker caching app shell and libraries. Full offline works for everything except upload (which requires the file present anyway).

## 11. Data Model

### 11.1 Canonical types (summary)

```ts
// Versioned base
interface Versioned { version: number; }

// Core
interface MidiNote { midi: number; ticks: number; durationTicks: number; velocity: number; channel: number; }
interface NormalizedProject extends Versioned { /* ppq, tempoMap, timeSignatures, tracks */ }

// Styles
interface StyleProfile { /* harmony, melody, rhythm, voicing */ }

// Analysis
interface Analysis { keyCandidates; chosenKey; melody; harmony; tempo; confidence; }

// Compose
interface AccompanimentRequest { roles; styleId; density; registers; seed; }
interface AccompanimentPlan { chordGrid; roles; ppq; key; tempo; }
interface AccompanimentResult { original; generated; meta; }

// Etude
interface EtudeConstraints { key; mode; styleId; difficulty; bars; tempo?; harmony; melody; rhythm; seed; }
interface Etude { canonicalId; instanceId; title; tempo; chords; melody; annotations; constraints; }

// Explore
type ExploreSeed = { kind: 'chord' | 'progression' | 'scale' | 'interval' | 'free'; ... };
interface Idea { id; source; chord?; progression?; scale?; melody?; seed?; tags?; }

// Pedagogy
interface Annotation { id; target; label; text; conceptId?; confidence?; }
interface Concept { id; title; category; definition; body; references?; related?; }

// Practice
interface PracticeSession { id; etude; metronome; tempoRamp; loop; abCompare?; attempts; }
interface LatencyCalibration { inputLatencyMs; outputLatencyMs; calibratedAt; }

// Session (top-level)
interface Session extends Versioned {
  mode: 'compose' | 'etude' | 'explore';
  globalTranspose: number;
  idea: Idea | null;
  compose?: { project; analysis; overrides; request?; };
  etude?: { constraints; current; exerciseTranspose; };
  explore?: { seed; history; };
}
```

### 11.2 URL serialization

Compact query-string form per mode:

```
/app?mode=etude&style=jazz&key=C&mode=major&diff=3&bars=8&seed=1234&transpose=1
/app?mode=compose&fileHash=sha256:...&key=Cmaj&style=jazz&roles=bass,chords&seed=99
/app?mode=explore&seed=chord:Cmaj7
/play?idea=<base64>
```

Uploaded file content is never in the URL  -  represented by hash.

### 11.3 Migrations

Every serialized object carries `version`. Migrations live in `engine/migrations/` and run in sequence on load. If a migration fails, load the object in a best-effort read-only state and warn the user.

## 13. Risks & Mitigations

| # | Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|---|
| R1 | Analysis accuracy poor on real-world MIDI | High | High | Golden-file test corpus; prominent user overrides; confidence-based UI |
| R2 | Scope creep across four layers delays launch | High | High | Phased rollout; ship layer-by-layer; defer P2/P3 |
| R3 | Web MIDI browser support varies | Medium | Medium | On-screen piano and computer keyboard as fallbacks |
| R4 | Audio latency / performance poor on low-end devices | Medium | Medium | Offline rendering for export; lookahead scheduling; performance budget |
| R5 | Sample libraries have restrictive licenses | Medium | High | Ship with synth instruments only in v1; audit before adding samples |
| R6 | Generated content sounds "generic" or "wrong" | Medium | High | Style profiles grounded in idiom; user testing; rapid iteration on pattern library |
| R7 | Mobile UX falls apart under desktop-first assumptions | High | Medium | Touch-first on-screen piano; responsive layout; test on phones early |

| R9 | Reproducibility breaks when Date.now or Math.random leaks in | Medium | Medium | Lint rule banning Math.random in engine/; canonical ID scheme |
| R10 | Ear training feels bolted on | Medium | Low | Integrate with concept drawer; annotate prompts with concept IDs |

## 16. Appendices

### A. Glossary

- **Mode**  -  one of Compose, Etude, Explore.
- **Idea**  -  a portable musical fragment usable across modes.
- **Style Profile**  -  declarative object describing a genre's vocabulary.
- **Etude**  -  a short, focused study for deliberate practice.
- **Seed**  -  integer making a generator reproducible.
- **Effective Key**  -  sounding key after all transposition layers.
- **Annotation**  -  short explanation attached to a musical element.
- **Concept**  -  longer-form theory entry reachable from annotations.
- **Rootless Voicing**  -  chord voicing that omits the root.
- **Canonical ID**  -  deterministic ID from seed + constraints.
- **Instance ID**  -  unique ID per instantiation.

### B. Style Profiles (shipped in v1)

- Jazz  -  swing, extended harmony, ii-V-I.
- Classical  -  diatonic, stepwise, common-practice.
- Lo-fi / Neo-soul  -  dense 7th/9th voicings, modal interchange.
- Blues  -  12-bar, dominant, shuffle.
- Pop  -  four-chord loops, triadic.
- Modal / Ambient  -  static harmony, texture.

Full parameter values are in the Style Profiles reference.

### C. Accompaniment pattern library

Chord patterns for jazz (Freddie Green, Charleston), pop (block, pulse, offbeat), lo-fi (lazy), modal (sustain), classical (Alberti).

Bass patterns: walking, two-feel, root-fifth, eighth-pulse, shuffle-boogie, drone.

Full steps are in the Pattern Library reference.
